## [1.0.0] - 2026-09-01

### Changed (2026-09-03) — FM:Sample decoupled from level/velocity + factory preset smoothing pass

- **FM:Sample now modulates from the sample's PRE-level, PRE-velocity signal.** User: "decouple fm modulation from sample velocity. i want to modulate with the sample volume at 0." New `SamplePlayer::lastRawSample()` taps the fully-processed sample (trim/fades/AD env/HP/LP/crush) BEFORE the final `x sampleLevel x velFactor` multiply; `KickVoice::renderStereo` feeds that tap — scaled by the smoothed `sampleGate` — into `BodyOscillator`'s FM:Sample modulator instead of the audible post-level output. Results: **SAMPLE level at 0 = silent sample, full warp** (measured RMS-deviation-from-sine 0.43 at amount=1, vs exactly 0 before); **velocity no longer changes the warp depth** (at velSens=0, hits at different velocities render bit-identically; at velSens=1, velocity scales LEVEL exactly ~2x between full/half velocity while the waveform shape holds within the deliberate velocity->sampleLP darkening); and the `sampleGate` scaling also fixes the code-review CONFIRMED bug where toggling SAMPLE off mid-note kept an inaudible modulator warping the body — it now fades out click-free in ~5 ms. This also resolves the review's "FM depth silently coupled to the SAMPLE level knob" finding. `morphMode` tooltip updated ("its LEVEL can sit at 0 for silent modulation").
  - Tests: 3 new blocks — silent-modulation-at-level-0, velSens=0 velocity-inert (identical renders), velSens=1 proportionality (level scales, shape holds; the limiter is bypassed in these renders since a nonlinear stage would break the proportionality measurement).
  - Files: `Source/DSP/SamplePlayer.{h,cpp}`, `Source/DSP/KickVoice.cpp`, `Source/Parameters/ParameterDescriptions.h`, `Source/Tests/RunTests.cpp`.
- **Factory preset smoothing pass (24 value edits across 20 of the 47 presets).** User: "make the presets smoother. more realistic and similar to iconic drum machines." Softened the brightest clicks (`clickTone` pulled down 500-1200 Hz where it sat 3.5-6 kHz, `clickTime` lengthened ~1-2 ms for a rounder beater edge on the acoustic kits), eased the harshest `transientAttack`/`drive`/`character` values (e.g. Lo-Fi Knock's character 0.70->0.60, off the Foldback edge), and moved the 808 group closer to the real TR-808's bridged-T behaviour (808 Classic: sweep 1.6x/60ms -> 1.5x/45ms, click 0.15/2.5kHz -> 0.10/2kHz, drive 0.15 -> 0.10; similar trims on Long/Punch/Knock). House is now explicitly a warmer 909-in-a-house-track voicing (sweep 3.0->2.6, click 3.5k->2.8k). The deliberately-hard genre presets (Hardstyle, Hardcore, Schranz, Acid Kick, Minimal Tick, Distorted, Clicky) are untouched — aggression is their point.
  - Tests: the 47-preset suite still passes untouched — every preset renders finite/audible/bounded and all 47 stay mutually distinct (47/47 distinct RMS).
  - Suite: 300/300 PASS, 0 failures. Full VST3+AU build/install, 0 warnings.
  - Files: `Source/Presets/PresetManager.cpp`.

### Fixed (2026-09-03) — AM / RM warp modes too subtle

- **AM and RM now sound clearly "detuned/metallic" instead of barely-there.** User: "AM FM FROM SAMPLE AND RM Dont work or effect too subtle." Investigated with a new RMS-deviation-from-sine measurement per mode (isolated body, attack window, amount=1): every mode was already producing real, finite, non-zero output — not a dead-code bug — but `BodyOscillator::kModRatio` (the shared FM/AM/RM internal modulator's frequency, as a multiple of body pitch) was an exact `2.0`. An integer ratio is harmonically LOCKED to the carrier, so AM/RM were only reinforcing a harmonic already present in the carrier's own series — mathematically a real effect, but perceptually reads as "barely different" rather than the classic RM/AM "alien/metallic" character, which specifically needs an INHARMONIC modulator to produce sidebands that clash with the carrier. Changed `kModRatio` to `2.71` (`Source/DSP/BodyOscillator.h`). FM (which shares the same modulator) got noticeably more clangy too as a side effect (RMS deviation from a plain sine 0.38 -> 0.62 at amount=1); AM/RM's own deviation only shifted modestly (0.24 -> 0.25, 0.47 -> 0.50) since the improvement is mostly in beating/roughness character, which a simple time-domain difference doesn't fully capture.
  - **"FM:Sample doesn't work" was user error, not a bug** — confirmed by tracing `sampleEnable` (default OFF) through `SamplePlayer::renderSample()`, which internally silences itself (`params.enable < 0.5f` -> no work done) regardless of whether a sample is loaded in the bank. This is the exact "graceful degrade to no effect" behaviour from the original brief/tests. `morphMode`'s tooltip (`ParameterDescriptions.h`) now explicitly says FM:Sample needs SAMPLE turned on with something loaded.
  - **New permanent regression test:** every non-default `morphMode` must deviate from a plain sine by more than a floor (0.05, well under the smallest observed ~0.25) at amount=1 — would have caught a genuinely-dead mode automatically; the earlier per-mode stability sweep only checked finite/bounded, not "does something."
  - Suite: 289/289 PASS, 0 failures. Full VST3+AU rebuild/install.
  - Files: `Source/DSP/BodyOscillator.h`, `Source/Parameters/ParameterDescriptions.h`, `Source/Tests/RunTests.cpp`.

### Added (2026-09-02) — Morph warp modes

- **The Morph knob now has 8 selectable warp modes, Serum-Warp-style.** User: "i want to improve the morph knob make it have choices like serum's warp mode." Full ideation/research trail: `plugins/KICKR/.ideas/improvements/morph-warp-modes.md` + `morph-warp-modes-research.md`.
  - **New parameter `morphMode` (71 total, 5 Choice: `noiseType`/`oversampling`/`tuneMode`/`filterType`/`morphMode`):** an `AudioParameterChoice` picking which of 8 algorithms the existing `morph` knob now drives as a per-mode AMOUNT (0 = clean sine regardless of mode). Default 0 = **Bend/Skew**, exactly today's CZ-style attack-only phase-skew, unchanged — so every existing preset and any automation on `morph` alone sounds bit-identical unless `morphMode` is explicitly changed.
  - **The 8 modes (`Source/DSP/BodyOscillator.{h,cpp}`, `BodyOscillator::Mode`):** Bend/Skew (existing), **Sync** (hard sync — a second accumulator running at `1 + amount x 5` the body rate hard-resets the audible phase whenever it wraps), **Fold** (sine wavefolder, `y = sin(gain x x)`, analytically bounded regardless of gain), **FM** (self-FM via phase modulation against a shared fixed-ratio (2x) internal modulator, index capped at amount x 3 rad), **FM:Sample** (same phase-mod math, modulator is the Sample layer's live output instead of an internal oscillator — degrades gracefully to "no effect" when no sample is loaded/enabled), **PD** (Casio-CZ-style phase distortion — reuses Bend/Skew's exact warp curve but applied CONTINUOUSLY through the tail, not attack-only, which is what makes it read as genuinely different rather than a duplicate), **AM** and **RM** (share the same fixed-ratio internal modulator; AM shifts it unipolar before multiplying, RM leaves it bipolar — the classic AM-preserves-carrier vs RM-cancels-carrier distinction). Every mode except PD reuses the existing attack-only shaping envelope (`shapeEnv`, 40 ms decay) — the tail always relaxes toward a clean sine, keeping every mode "musical" on a kick rather than a sustained texture; this was an implementation-time judgment call flagged as open in the improvement brief, made consistent with the plugin's existing morph design philosophy ("the buzz of the harder shapes sat on the whole tail" — the reason v1 morph was replaced). Every mode's amount is tuned to a musical/tame ceiling at amount=1, not a textbook-extreme value (also flagged as an implementation-time tuning pass in the brief).
  - **`KickVoice::renderStereo` reorder:** the Sample layer now renders BEFORE the body oscillator each sample (previously after) so `Mode::fmFromSample` can thread the sample's current output into `body.renderSample(sampleM)` as its modulator. `sample.renderSample()` still runs exactly once per sample either way — output for every OTHER mode (which ignores the argument) is unaffected.
  - **UI (`Source/PluginEditor.{h,cpp}`):** a small combo box (`morphModeCombo`, the same `addCombo`/`ComboBoxParameterAttachment` pattern as `noiseType`/`oversampling`/`filterType`) sits above the Morph knob in its existing carved-out scope-panel slot; the knob itself is unchanged in size/position/color. Editor now binds 61 parameters (was 60).
  - **Tests (`RunTests.cpp`, new blocks):** all 8 modes x 4 oversampling factors x 3 amounts under machine-gun retrigger — finite, bounded (mirrors the existing per-mode-0 stress test); `Mode::fmFromSample` with no sample loaded renders an exact unmodified sine (no silence-driven garbage/NaN); an instant `morphMode` switch mid-note (Bend/Skew -> RM, the most different pair, at max amount) stays finite and bounded — mode switches are intentionally NOT crossfaded (same convention as `noiseType`/`filterType`/`tuneMode`, all instant Choice params already in this engine), so this checks the safety guarantee (no blow-up) rather than zero-slew smoothness; `morphMode` added to the state round-trip and hover-description-coverage tests. Suite: 288/288 PASS, 0 failures. Full VST3+AU build/install: clean, 0 warnings.
  - Affects: `Source/DSP/BodyOscillator.{h,cpp}`, `Source/DSP/KickVoice.{h,cpp}`, `Source/DSP/KickEngine.{h,cpp}`, `Source/Parameters/{ParameterIDs,ParameterLayout,ParameterDescriptions}.h`, `Source/PluginEditor.{h,cpp}`, `Source/Tests/RunTests.cpp`.

### Changed (2026-09-02) — Analyzer

- **Spectrum analyzer rebuilt Pro-Q-3 style; the high end now reads correctly.** User: "feels like the spectrum doesnt show the high end correctly, check it if yes make it propperly. look at how fabfilter pro q 3 works and implement the same settings." Confirmed: the old display plotted every FFT bin at its own level, so a kick's tonal low end (one bin, full level) looked fine while its broadband highs (spread over hundreds of tiny bins) sagged tens of dB below their real energy and drew as a jagged comb; and one 0.6 one-pole per bin smoothed attack and release alike, so the click barely registered.

### Changed (2026-09-02) — Limiter

- **The output limiter is now a Color Limiter (Ableton Color Limiter control set).** User: "change the limiter to an identical to abletons colour limiter" / "replace the limiter we have with colour limiter", transparent defaults. Ableton's algorithm is proprietary Max for Live code; this is a from-scratch limiter with the same six controls: **LOUDNESS** (input gain 0..+24 dB), **CEILING** (-24..0 dB), **LOOKAHEAD** (0.1..10 ms), **RELEASE** (1..1000 ms), **SATURATION** (0..1), **COLOR** (0..1), plus the existing on/off. Defaults 0 dB / -0.5 dB / 1.5 ms / 50 ms / 0 / 0.5 — the old ceiling, no saturation.
  - **DSP (`Source/DSP/ColorLimiter.{h,cpp}`, new; sits as step 5 of `OutputStage::processOutput`, in-region):** loudness gain → saturation (peak-normalised tanh, drive 1 + 3·SAT; COLOR tilts only the *generated* harmonics with a ±8 dB shelf pivoting at 500 Hz: low = warm/round, high = bright/crunchy — drive itself never changes with COLOR, so on a kick it is purely a tone control for the saturation) → stereo-linked look-ahead brickwall (required gain per input sample → sliding-window minimum over the look-ahead via a preallocated monotonic deque → one-pole attack (time constant = look-ahead / 3) / RELEASE envelope, applied to the signal delayed by exactly the look-ahead) → hard clamp at the ceiling as the final guarantee. Disabled = full bypass (no delay). All buffers allocated once in `prepare()` for the 10 ms @ 8x192 kHz worst case; an oversampling switch mid-note is coefficient-only and **resamples the held delay-line content** to the new rate with a self-contained seam fade (the seam lands one look-ahead after the switch, outside the engine's own 64-sample fade — the first version cleared the line and popped; caught by the existing OS-switching slew test, now 0.040).
  - **What changed for existing sounds:** the old stage was a memoryless `tanh` soft-clip at -0.5 dBFS that coloured anything hotter than about -10 dBFS. Now the look-ahead brickwall does the limiting and the last stage is a clamp that adds nothing below the ceiling, so hot presets come out at the same level but cleaner / slightly more dynamic; quiet material is bit-identical apart from the 1.5 ms delay. Dial in SAT for the old-style softness and more.
  - **Latency:** the look-ahead (default 1.5 ms = 72 samples @ 48 kHz) is reported to the host on top of the oversampling latency, updated live from `limiter` / `limLookahead` changes (`KICKRAudioProcessor::limiterLatencySamples()`); the scope's note-on capture is offset by the same amount so its sample 0 stays the (delayed) onset. The engine's base-rate safety clamp now follows the CEILING knob instead of the hard-coded -0.5 dBFS.
  - **Parameters:** 6 new floats (`limLoudness`, `limCeiling`, `limLookahead`, `limRelease`, `limSaturation`, `limColor`; 66 APVTS params total, 58 Float), all on the Randomize/Mutate exclusion list. Existing sessions load with the defaults above.
  - **UI:** the reserved engine-strip cell (ex-TUNING) is now **LIMITER**. Follow-up the same day — user: "remove the output section give limiter the space and place the oversampling with the limiter" — the OUTPUT cell is gone: LIMITER spans the last two engine slots, the oversampling selector sits beside the on/off pill, and the six knobs are Medium size (LOUD / CEIL / LOOK over REL / SAT / COLOR). `output` (GAIN) and `mix` remain in the APVTS at their defaults (0 dB / 1.0) with no control — LOUDNESS is the gain now. Editor binds 60 parameters.
  - **Tests (`RunTests.cpp`, new block, 13 checks; suite 0 failures):** default limiter == bypass delayed by the look-ahead (max diff 0.00000 on a -20 dB kick); ceiling never exceeded at -0.5 / -6 / -12 dB under +12 dB output, +24 dB loudness, full saturation (peaks land exactly on the ceiling gain); LOUDNESS +12 dB raises RMS 0.275 → 0.367 at the same peak; SATURATION 0.8 lifts (h3+h5)/f from 0.002 to 0.096; COLOR 1 vs 0 doubles the upper-harmonic ratio (0.016 → 0.033); RELEASE 1 ms vs 1000 ms: 300–500 ms RMS 0.65 vs 0.24; reported latency follows LOOKAHEAD (5 ms → 240 samples) and drops to 0 when off; finite and on-ceiling under 24-hit machine-gun retrigger at all four oversampling factors. Existing latency tests updated to include the look-ahead.
