- **Fixed 2026-08-31 — full code review (`/code-review`), 7 verified findings fixed:**
  1. **Retrigger crossfade still killed a still-playing sample (KickEngine.cpp).** The synth crossfade completing (~3 ms after ANY retrigger) unconditionally called the outgoing voice's `reset()` — including its `SamplePlayer` — bypassing the session's earlier voice-lifetime fix entirely via a second, unpatched code path. This meant a normal 2-hit retrigger with a long sample killed the first hit's sample ~3 ms after the second hit, every time — the single biggest remaining cause of "the sample doesn't play whole." Fix: the outgoing voice is now only reset if `!isActive()`; otherwise it's demoted to a new `retiringVoice` slot that keeps rendering (unscaled — its own gates/envelope already govern audibility) until it finishes naturally, or a 3rd trigger legitimately steals the slot (an unavoidable limit of the 2-voice architecture). New regression test bank-swaps the loaded sample between two triggers (a `SamplePlayer` captures its buffer pointer at `noteOn`, so the first voice keeps reading the first file even after the swap) and confirms both frequencies are present well after the crossfade.
  2. **Data race on `KickVoice::active` (KickVoice.h).** A plain `bool`, written by the audio thread and read cross-thread by `PluginProcessor::retireUnreferenced()` (message thread) via `KickEngine::anyVoiceActive()`, with no synchronisation — undefined behaviour that gates whether a retired `SampleBuffer` is safe to free; a stale/never-visible read could free memory the audio thread still holds a raw pointer into. Changed to `std::atomic<bool>` (drop-in — same read/write syntax works via the implicit conversion/assignment operators).
  3. **Reverse + `sampleAttack` inverted the fade-in (SamplePlayer.cpp).** The reversal fix mirrors the AD envelope (`1-env`) so it rises across playback instead of decaying — but that mirror was applied uniformly across BOTH the attack and decay phases, so a nonzero `sampleAttack` on a reversed sample became a fade-*out* right at the start, with a discontinuity at the attack/decay boundary. Fix: reverse now skips the separate attack phase entirely (it already gets an equivalent 0→1 fade-in for free from the mirrored decay curve) rather than fighting it.
  4. **Macro knobs (Punch/Body/Crush/Tail) took ~10 seconds to reach their target (KickEngine.cpp).** Their `SmoothedValue`s were `reset()` against `baseSampleRate` (calibrated for one `getNextValue()` tick per *sample*) but only ever ticked once per `processBlock()` call — once per host *block*. At a typical 512-sample buffer the documented "~20 ms" ramp actually took ~20 ms worth of blocks, i.e. ~10 s, scaling with the host's buffer size. Fix: calibrate against block-rate (`baseSampleRate / maxBlockSize`) instead of sample-rate. New regression test isolates a sustained (long-tail) signal and compares a stepped render against an already-at-target control at the same absolute time, confirming convergence within ~20–40 ms.
  5. **`Analyzer` waveform generation/write-position torn read (Analyzer.cpp).** `getWaveform()` read the generation tag and the write-position as two *separate* atomics; `armCapture()` writes them as two separate stores, so a message-thread read landing between the two could pair the old generation with the new (reset) position — a torn snapshot (benign: at most a one-frame display glitch, not a memory-safety issue). Packed both into a single `std::atomic<std::uint64_t>` (generation in the high 32 bits, write-position in the low 32) so one load/store always yields a consistent pair.
  6. **Stale `sampleDecay` fallback default (KickEngine.h / .cpp).** The `Snapshot` struct's default and the defensive `load(pSampleDecay, ...)` fallback were left at the pre-fix `800.0f` when the actual param default was raised to `2200.0f` earlier this session — only reachable if the cached APVTS pointer is ever null, but a real leftover inconsistency. - **Fixed 2026-08-31 — sample reversal didn't play whole ("sometimes").** User: "during sample reversal the sample doesn't play whole some times." Three compounding bugs, all in `SamplePlayer`/`KickVoice`:
  1. **Root cause (`SamplePlayer::renderSample`):** the AD envelope decays in *real time* from `noteOn` (voice age) — loud at t=0, quiet later — completely independent of read direction. A one-shot's loud content sits at its recorded start; in `sampleReverse` that content is read *last*, so by the time playback reached it the envelope (already decayed toward silence) had killed it. Forward playback hid this because its own shape (loud start → quiet tail) happens to match a typical sample. **Fix:** for `sampleReverse`, apply the *mirror* of the decay curve (`1 − env`, rises across `sampleDecay` then holds near 1) instead of the curve itself, and skip the envelope-floor early-finish for reverse (only the trim-window boundary ends reverse playback — the mirrored envelope never approaches a "floor").
